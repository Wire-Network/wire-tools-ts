# Nonbootstrap roster replacement

A real replacement posts depot collateral, starts its daemon and joins the scheduled roster. The scenario reads both deployed outposts, then executes the fresh Ethereum custody/shadow/redemption journey. It requires the replacement's accepted Ethereum delivery digest and its recorded Solana consensus vote matching the accepted envelope audit checksum, with the destination cursor already past that epoch. Chunk staging and stale transaction success are insufficient. No bootstrap-only account is accepted as replacement evidence. Run with the canonical runner and heartbeat monitor.

The scenario uses the normal three-group lookahead window (one member per group) so existing operators can seat new membership before the replacement serves. Its new Solana signer receives the standard operator gas/rent funding through an explicit provisioning Step.
